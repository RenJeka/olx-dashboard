# Старт сесії

Лише читання: нічого не змінювати ні в репо, ні на проді. Правила — [`docs/rules.md`](../../docs/rules.md).

## 1. Контекст із репо

1. [`docs/current.md`](../../docs/current.md) — повністю.
2. Останній хендоф у `docs/handoffs/` (найпізніша дата в імені; кілька за день — усі за цю дату):
   розділи «Current state», «Open items», «Dead ends».
3. Шапки активних планів: рядок `> **Статус:**` кожного `docs/plans/*.md` (без `old/`).
4. Якщо здається, що правил `AGENTS.md` не видно, — [agents-md-loading](../../docs/instructions/agents-md-loading.md).

## 2. Звірка з живим станом (дешево, лише читання)

- **Git:** `git branch --show-current`, `git status --short`, `git log --oneline -3`,
  `git fetch --quiet && git log --oneline -1 origin/main`.
- **CI `main`:** `https://api.github.com/repos/RenJeka/olx-dashboard/actions/runs?branch=main&per_page=1`
  (публічно, без токена) — `conclusion` і `head_sha`.
- **Render** (якщо MCP доступний): `list_services` → сервіси `olx-dashboard-api` і `olx-dashboard` —
  гілка; `list_deploys` (limit 1) — статус і коміт live-деплою; збігається з `origin/main`?
- **Turso:** не чіпати без потреби (`AGENTS.md` → «Turso-економія»). Лише якщо `current.md` чи хендоф прямо чекають перевірки БД —
  спершу спитати людину.
- MCP недоступний — сказати про це одним рядком, не обходити.

## 3. Відповідь

Короткими блоками, без переказу файлів:

- **Де ми:** 1–2 речення зі стану.
- **Що розходиться:** лише розбіжності між `current.md` / хендофом і живим станом (гілка, незакомічене,
  CI, деплой). Нема — «розбіжностей немає».
- **Пропоную:** один перший крок (зазвичай «Наступний крок» з `current.md`) + 1–2 альтернативи з
  відкритих питань. Далі чекати відповіді людини.

Якщо `current.md` і живий стан розходяться — показати розбіжність і спитати, чому вірити.
