# Завершення сесії

Мета: усе, що варто пам'ятати, лягає у файли, і кожен факт має одне місце. Правила —
[`docs/rules.md`](../../docs/rules.md), формати — [`docs/templates/`](../../docs/templates/).

## 1. Збір

Перечитай **усю** розмову (не лише кінець) і випиши як знімок стану, не хронологію:

- рішення й причини (хто вирішив); глухі кути; поправки людини; обмеження, згадані один раз;
- що створено чи змінено (файли, гілки, PR, деплої, ресурси Render/Turso) і статус кожного;
- відкриті питання й **один** наступний крок;
- відкладене («потім», «не зараз») → кандидати в парковку;
- нові пастки й глухі кути → кандидати в інструкції;
- процедури з кроками → кандидати в скіли;
- стабільні поправки людини щодо роботи → кандидати в `docs/rules.md` (лише пропозиція);
- секрети не записувати — лише де лежать ([secrets-in-sources](../../docs/instructions/secrets-in-sources.md)).

Прочитай `docs/current.md`, `docs/parking.md`, `docs/instructions/README.md`, шапки активних планів.
Пошукай (Grep), чи тема вже є: дублікатів не створювати.

## 2. План без запису

Покажи таблицю «Файл | Дія | Що саме» і чекай підтвердження. Пункти до розгляду:

1. **Плани** `docs/plans/`: відмітити виконані кроки й оновити статус за `AGENTS.md` → «Конвенції» →
   «Плани» (новий, ще не доданий у git план переносити в `old/` звичайним `mv`).
2. **Інструкції** `docs/instructions/`: нові файли (скіл `instruction-add`) з рядком у README;
   наявні оновлювати замість дублів.
3. **Парковка** `docs/parking.md`: нові записи (`parking-add`); закриті — прибрати й згадати в хендофі.
4. **Хендоф** у `docs/handoffs/` за [шаблоном](../../docs/templates/handoff.md); ім'я й дата — за
   `docs/rules.md` → «Хендофи».
5. **`docs/current.md`**: переписати актуальний стан, прибрати застаріле.
6. **Доменна документація** за правилами `AGENTS.md` → «Конвенції» (architecture/structure,
   business-rules, olx-api), якщо сесія змінювала код — перевірити, що вже оновлено.
7. **Скіли**: для кожної нової процедурної інструкції запропонувати скіл (`skill-from-instruction`).
8. **`AGENTS.md`**: лише якщо змінилась карта документації, інваріанти чи команди.
9. **Коміт** — за `docs/rules.md` → «Git».

Людина може викреслити пункти або додати свої.

## 3. Запис після підтвердження

Записувати в порядку плану. Того, чого немає в плані, не додавати.

## 4. Перевірка

- `npm run check` — дивитись на код виходу, не на хвіст виводу
  ([pipe-hides-exit-code](../../docs/instructions/pipe-hides-exit-code.md)).
- Принципи документації з `docs/rules.md` (DRY за таблицею «Де живе факт», без кількостей, що
  застаріють).
- Пошук за маркерами з [secrets-in-sources](../../docs/instructions/secrets-in-sources.md) по змінених
  файлах не знаходить значень секретів.
- Карта в `AGENTS.md` збігається з реальною структурою `docs/`.

## 5. Завершення

Покажи `git status --short`, запропонуй текст коміту (`docs/rules.md` → «Git») і скажи, що й де записано.
