# Секрети в джерелах (чат, хендоф, файл у репо, вивід команди)

## Коли застосовувати
Бачиш токен, ключ чи пароль у тексті, файлі або виводі; готуєш хендоф чи коміт.

## Що робити
- Що вважається секретом і що дозволено зберігати в `.env` — `AGENTS.md` → «Безпека».
- Де лежать секрети: застосунку — `server/.env` (локально) і env сервісів у Render; ключі доступу агента
  (Render API key, токени Turso) й бекапи прод-БД — `C:\Users\dell\.config\olx-dashboard\` (поза репо).
- Не копіювати секрет у файли, хендофи, коміти чи підсумок. Писати, **де** він лежить.
- Новий секрет людина кладе у файл сама (шлях — абсолютний, [absolute-paths-for-user](absolute-paths-for-user.md)),
  агент читає його з файлу. Показувати лише маску: перші символи + `…` + останні (`rnd_ab12…cd34`).
- Секрет засвітився (чат, лог, коміт) — сказати людині без цитування й запропонувати відкликати/ротувати.
- Файл із секретом опинився в репо — `*.env` і `.env.*` уже в `.gitignore`; перенести файл у теку
  ключів агента (вище).
- Перед комітом — пошук маркерів по змінених файлах: `rnd_`, `sk-or-`, `GOCSPX-`, `ghp_`,
  `github_pat_`, `eyJ` (JWT, токени Turso), `PRIVATE KEY`, `TURSO_AUTH_TOKEN=`, `SESSION_SECRET=`,
  `OPENROUTER_API_KEY=`, `password`, `пароль`, `token=`.

## Чого не робити
- Не виводити env цілком (`printenv`, `cat server/.env`, env сервісу з Render MCP зі значеннями) —
  достатньо назв змінних.
- Не зберігати «для зручності» навіть тестові ключі.

## Як перевірити
Пошук за маркерами не знаходить значень секретів. Збіги в прозі («ключ лежить у `render.env`») — нормально.
