# CRLF ламає точні заміни, а `sed -i` переписує весь файл

## Коли застосовувати
Правиш файл точною заміною (Edit, скрипт) або `sed -i` у Git Bash на Windows (`core.autocrlf=true`).
Особливо — одразу після `git pull` / `merge` / `switch`: файли, які щойно створено з LF, git у робочій
копії перезаписує вже з CRLF, і багаторядкова заміна скриптом, що працювала годину тому, падає з «не
знайдено» (сесія 2026-10-03).

## Що робити
- Перевірити кінці рядків: `grep -c $'\r' <file>` (0 — LF).
- Для CRLF-файлу: node-скрипт «прочитати → `\r\n`→`\n` → заміна → назад `\n`→`\r\n` → записати».
- Після правки — `git diff --stat <file>`: змінено кілька рядків, а не весь файл.

## Чого не робити
- Не запускати `sed -i` по CRLF-файлах: Git Bash прибирає `\r`, і diff показує зміну кожного рядка.
- Не підганяти шаблон заміни під `\r` вручну.

## Як перевірити
`git diff --stat` показує лише очікувані рядки.
