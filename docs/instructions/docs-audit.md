# Аудит документації на актуальність

## Коли застосовувати
Людина просить перевірити документацію чи парковку на актуальність, прибрати застаріле; або документи
помітно розійшлися з кодом після серії змін.

## Що робити
1. **Обсяг:** `AGENTS.md`, `README.md`, `docs/*.md`, `docs/instructions/`, `docs/parking.md`, активні
   `docs/plans/*.md`, проєктні `skills/*/SKILL.md` + коментарі коду з шляхами `docs/…`. Хендофи й `docs/plans/old/`
   не чіпати — знімки з датою ([rules](../rules.md) → «Хендофи»). Сторонні скіли (без посилань на `docs/`) — поза обсягом.
2. **Механічні перевірки (спершу, з Git Bash у корені репо):**
   - шляхи з доків, яких немає в репо: витягнути `` `…\.(ts|tsx|mjs|sql|md)` `` з файлів обсягу й перевірити
     `git ls-files | grep "/<ім'я>$"` — порожньо → файл видалено чи перейменовано (`git log --diff-filter=D --name-only`);
   - зворотно — файли коду, яких немає в `docs/structure.md`: для кожного `git ls-files server/src web/src scripts`
     (без `*.test.ts`) — `grep -q <ім'я без розширення> docs/structure.md`;
   - шляхи до планів у коді: `grep -rhoE "docs/plans/[a-zA-Z0-9_-]+\.md" server/src web/src scripts` — план лежить
     уже в `old/` → оновити шлях ([plan-archive-links](plan-archive-links.md));
   - позначки «ще не / заплановано / ⏳ / TODO» — звірити з кодом, чи не зроблено;
   - точні значення, що змінюються (див. п. 3): `grep -nE "[0-9]+(px|vw|vh)|PR #[0-9]+|[0-9a-f]{7,} |v?[0-9]+\.[0-9]+\.[0-9]+"`;
   - назви з UI (кнопки, розділи налаштувань), ідентифікатори моделей і константи — `grep` у `web/src` / `server/src`;
   - стан, прив'язаний до ПК (шляхи `C:\Users\<ім'я>`, встановлені інструменти, MCP) — перевірити на поточному ПК
     (`claude mcp list`, `Test-Path`); у тексті позначати «домашній ПК» / «робочий ПК»;
   - `npm run docs:check` — биті посилання.
3. **Неактуальне** — якщо хоч одне:
   - розходиться з кодом чи `server/src/db/schema.sql` (вірити коду — [rules](../rules.md) → «Джерела істини»);
   - зроблене чи закрите описано як «треба зробити» (кроки планів, відкриті питання, умова «коли повернутися»
     в парковці, що вже настала);
   - **виконаний запис парковки** — прибрати повністю й згадати в хендофі ([rules](../rules.md) → «Парковка»);
   - дублює факт, що живе деінде ([rules](../rules.md) → «Де живе факт», карта в `AGENTS.md`): **одне джерело
     правди** — у джерелі факт, в інших місцях лише посилання;
   - бракує перехресного посилання: документ згадує тему, яку веде інший документ, без посилання на нього; або
     документ ні звідки не досяжний (немає в карті `AGENTS.md`, `instructions/README.md`, `structure.md`);
   - містить кількості чи точні значення, що змінюються з кодом ([rules](../rules.md) → «Принципи документації»,
     п. 2): лічильники, версії пакетів, номери PR, хеші, значення верстки компонентів;
   - розповідь чи історія в живому документі замість стану (історія — хендофи й `plans/old/`).
4. Перевіряти фактами: Grep/Read коду, `git log`, `gh`; прод — лише читанням ([rules](../rules.md) → «Прод»).
5. **Звіт людині до правок** — таблиця з номерами рядків: файл → що не так → дія (`видалити` / `скоротити` /
   `перенести в <файл> одним реченням` / `оновити` / `замінити посиланням на <джерело>`). Сумнівне — окремим
   списком питань. Наприкінці — що прочитано повністю, а що перевірено лише пошуком.
6. Після «так» — правки: неактуальне видалити; важливе з видаленого — до одного речення в правило,
   інструкцію чи профільний документ (одне місце — DRY). Закриті `P-NNN` прибрати й згадати в хендофі;
   завершені плани — ✅ і `git mv` у `plans/old/` ([plan-archive-links](plan-archive-links.md)).
7. `npm run check` зелений.

## Чого не робити
- Не правити до погодження звіту людиною.
- Не переписувати хендофи й `plans/old/` (виняток — вирізати секрети).
- Не переносити видалене «про всяк випадок» повним текстом — лише суть одним реченням або нічого.
- Не замінювати застаріле число новим числом — замінити посиланням на джерело (код, `package.json`, живий запит).

## Як перевірити
Звіт погоджено, правки внесено, `npm run check` зелений; механічні перевірки п. 2 не дають нових збігів; у живих
документах немає кількостей, змінних точних значень, дублів фактів і закритих пунктів.
