# Аудит документації на актуальність

## Коли застосовувати
Людина просить перевірити документацію чи парковку на актуальність, прибрати застаріле; або документи
помітно розійшлися з кодом після серії змін.

## Що робити
1. **Обсяг:** `AGENTS.md`, `README.md`, `docs/*.md`, `docs/instructions/`, `docs/parking.md`, активні
   `docs/plans/*.md`, `skills/*/SKILL.md`. Хендофи й `docs/plans/old/` не чіпати — знімки з датою
   ([rules](../rules.md) → «Хендофи»).
2. **Неактуальне** — якщо хоч одне:
   - розходиться з кодом чи `server/src/db/schema.sql` (вірити коду — [rules](../rules.md) → «Джерела істини»);
   - зроблене чи закрите описано як «треба зробити» (парковка, кроки планів, відкриті питання);
   - дублює факт, що живе деінде ([rules](../rules.md) → «Де живе факт»);
   - містить кількості чогось ([rules](../rules.md) → «Принципи документації», п. 2);
   - розповідь чи історія в живому документі замість стану (історія — хендофи й `plans/old/`).
3. Перевіряти фактами: Grep/Read коду, `git log`, `gh`; прод — лише читанням ([rules](../rules.md) → «Прод»).
4. **Звіт людині до правок** — таблиця: файл → що не так → дія (`видалити` / `скоротити` /
   `перенести в <файл> одним реченням` / `оновити`). Сумнівне — окремим списком питань.
5. Після «так» — правки: неактуальне видалити; важливе з видаленого — до одного речення в правило,
   інструкцію чи профільний документ (одне місце — DRY). Закриті `P-NNN` прибрати й згадати в хендофі;
   завершені плани — ✅ і `git mv` у `plans/old/`.
6. `npm run check` зелений.

## Чого не робити
- Не правити до погодження звіту людиною.
- Не переписувати хендофи й `plans/old/` (виняток — вирізати секрети).
- Не переносити видалене «про всяк випадок» повним текстом — лише суть одним реченням або нічого.

## Як перевірити
Звіт погоджено, правки внесено, `npm run check` зелений, у живих документах немає кількостей і закритих пунктів.
