# Порт 3001 зайнятий `npm run dev` людини; `SQLITE_BUSY` від старих dev-серверів

## Коли застосовувати
Агент запускає локальний сервер для smoke і бачить `EADDRINUSE 0.0.0.0:3001`, або запити йдуть, а логів у
своєму виводі немає. Або людина не може запустити `npm run dev`: старт падає з `SQLITE_BUSY: database is locked`.

## Що робити
- Перевірити, хто слухає порт (PowerShell): `Get-NetTCPConnection -LocalPort 3001 -State Listen` → процес.
  Зазвичай це `tsx watch src/index.ts` людини: він сам підхоплює правки коду, але логи пише у свій термінал.
- Свій сервер — на іншому порту, без watch: у `server/` `PORT=3002 npx tsx src/index.ts > <лог> 2>&1 &`,
  запити на `localhost:3002`, після перевірки — зупинити процес за PID.
- `NODE_ENV=production` дає JSON-логи pino (без pino-pretty) — зручно шукати `grep`.
- **`SQLITE_BUSY` на старті:** файл `server/data/olx.db` тримає інша копія сервера. Буває, що це завислі
  `tsx watch src/index.ts` з минулих сесій (агентів чи людини): вони живуть днями й самі перезапускаються,
  коли змінюється файл, і знову займають і порт, і базу. Знайти (PowerShell):
  `Get-CimInstance Win32_Process -Filter "Name='node.exe'" | Where-Object { $_.CommandLine -match 'tsx|run dev|concurrently|vite' } | Select-Object ProcessId,ParentProcessId,CreationDate`.
  Показати людині список з датами запуску → після її «так» зупинити деревом: `taskkill /PID <pid> /T /F`.
- Свій сервер агент зупиняє одразу після перевірки (деревом, за PID кореня), щоб не лишати watch-процесів.

## Чого не робити
- Не зупиняти процес людини на 3001 без її згоди (2026-10-05 агент так зробив: прийняв сервер людини за свій,
  бо не перевірив `EADDRINUSE` у своєму лозі; наслідок — людині довелося розбиратися з `SQLITE_BUSY`).
- Не робити висновків з логів, яких не бачиш: запит на 3001 обробив сервер людини.

## Як перевірити
Рядки потрібного логу з'являються у файлі логу свого сервера.
