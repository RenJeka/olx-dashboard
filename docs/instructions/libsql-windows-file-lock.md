# libSQL на Windows тримає файл БД до виходу з процесу

## Коли застосовувати
Скрипт чи тест відкриває локальну БД через `@libsql/client` (`file:…`) і потім хоче цей файл перейменувати,
перемістити чи видалити в тому ж процесі: `EPERM, Permission denied` / `EBUSY`, навіть після `client.close()`.

## Що робити
- Вважати файл зайнятим до кінця процесу (перевірено 2026-10-16: `close()` + повтори `renameSync` 2 с — не допомагає).
- Перейменування/бекап робити **до** відкриття клієнта, а писати одразу у фінальний шлях (так зроблено в
  `server/src/copyProd.ts`).
- Тимчасові БД тестів — з префіксом `olx-dashboard-test-` у `tmpdir()`: залишки старші за годину прибирає
  `server/src/test/globalSetup.ts`; збій `rmSync` в `afterEach` ковтати.

## Чого не робити
- Не писати в тимчасовий файл з планом «перейменую після `close()`» — на Windows перейменування впаде.
- Не імпортувати `server/src/db/db.ts` у скрипт, який перейменовує `olx.db`: модуль відкриває файл одразу при імпорті.

## Як перевірити
Скрипт закінчується без `EPERM`; у `server/data/` немає «осиротілих» тимчасових файлів.
