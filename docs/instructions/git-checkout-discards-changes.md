# `git checkout -- <file>` знищує незакомічені правки

## Коли застосовувати
Хочеш «прибрати» тестову зміну у файлі, де є й інші незакомічені правки (свої чи людини).

## Що робити
- Спершу `git diff <file>` — подивитись, що саме відкотиться.
- Відкочувати точково: прибрати лише свій фрагмент правкою файлу.
- Перед експериментом зберегти стан: `git stash push -- <file>` або копія файлу в scratchpad.

## Чого не робити
- Не використовувати `git checkout -- <file>` / `git restore <file>` / `git reset --hard` для
  «прибирання», коли в робочій копії є чужі чи ще потрібні правки: вони зникають без можливості відновити.

## Як перевірити
Після прибирання `git diff <file>` показує лише те, що мало лишитись.
