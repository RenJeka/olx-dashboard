# Дані з прод-БД агенту: через Turso MCP, не через ключі

## Коли застосовувати
Агенту треба кілька сотень рядків з проду (Turso) у файл — для пілоту, аналізу, тесту на реальних даних.

## Що робити
- Ключі агента з теки поза репо ([secrets-in-sources](secrets-in-sources.md)) агент **не читає**: auto-mode
  Claude Code блокує це як «Credential Exploration» (так само — `server/src/env.ts`). Не обходити.
- **Шлях 1 — Turso MCP `read_database`** (лише читання, токен не потрібен). Щоб не переписувати екранований
  вивід вручну, брати одразу JSON: `SELECT json_group_array(json_object('id',id,…)) FROM (… LIMIT 50 OFFSET n)`,
  частинами по 50; довгі поля обрізати в SQL (`substr(description,1,1500)`). Вивід агент переносить у файл
  (знімаючи один рівень екранування), кожну частину перевіряє `node -e "require('./partN.json').length"`.
  Повільно для великих обсягів — брати мінімально потрібну вибірку.
- **Шлях 2 — команда людини:** людина в PowerShell задає `TURSO_DATABASE_URL`/`TURSO_AUTH_TOKEN` у сесії й
  запускає скрипт з лише SELECT (напр. `npm run jev:pilot -- --export <searchId>`); змінні сесії сильніші за
  `server/.env`. Секрет до агента не потрапляє.
- Turso-квота: спершу дешевий запит з `COUNT`/`SUM` по потрібному `search_id`, потім вибірка.

## Чого не робити
- Не читати теку ключів чи `.env` іншим інструментом / в обхід блокування.
- Не тягнути через MCP тисячі рядків — це і квота Turso, і контекст агента.

## Як перевірити
Файл вибірки валідний JSON, кількість рядків і перший/останній `id` збігаються із запитом.
