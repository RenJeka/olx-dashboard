# `docs:check` локально бачить незакомічені файли, CI — ні

## Коли застосовувати
Пишеш у документацію шлях у бектиках (`` `docs/…` ``, `` `.claude/…` ``, `` `server/…` `` тощо) або
markdown-посилання на файл, якого немає в git (untracked, локальний конфіг), — або локально
`npm run check` зелений, а в CI `docs:check` падає.

## Що робити
- Перевірка (`scripts/check-doc-links.mjs`) шукає ціль на диску, тож локальний untracked-файл
  «існує», а в CI — ні.
- Про локальні/незакомічені файли писати без бектиків і без посилання (звичайним текстом).
- Сумніваєшся — прогнати `npm run docs:check`, тимчасово перемістивши такий файл у scratchpad
  (і повернути назад).

## Чого не робити
- Не вважати локальний зелений `docs:check` гарантією для CI, якщо в робочій копії є untracked-файли,
  на які посилається документація.

## Як перевірити
`gh run watch <id> --exit-status` для пушу — exit 0 ([github-cli](github-cli.md)).
