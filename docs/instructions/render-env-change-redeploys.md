# Зміна env на Render передеплоює сервіс

## Коли застосовувати
Треба змінити змінну середовища сервісу Render (`NODE_VERSION`, `WEB_ORIGIN`…), особливо коли
сервіс деплоїться не з тієї гілки чи деплой зараз небажаний.

## Що робити
- У dashboard Render зберігати через **Save only** (без rebuild), якщо деплой зараз не потрібен; зміна
  набуде чинності з наступним деплоєм.
- Якщо одночасно змінюються гілка й env — спершу гілка, потім env, і один свідомий деплой.
- Дозвіл на зміну env — за [`docs/rules.md`](../rules.md) → «Прод». Гілку сервісу Render MCP змінити не
  вміє — це робить людина в dashboard.

## Чого не робити
- Не натискати «Save, rebuild and deploy», коли сервіс дивиться на застарілу гілку: передеплоїться
  старий код.

## Як перевірити
Render MCP `list_deploys` — нового деплою не з'явилось (або з'явився рівно один запланований).
