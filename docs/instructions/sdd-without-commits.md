# План агентами без комітів: diff задачі зі знімків робочої теки

## Коли застосовувати
План виконують агенти по задачах (виконавець → рецензент, скіл `superpowers:subagent-driven-development`), а коміт —
лише за словом людини (`docs/rules.md` → «Git»). Скіл чекає комітів після кожної задачі й будує diff `BASE..HEAD`
з них; без комітів рецензенту нема чого дати.

## Що робити
- Виконавцям — «не комітити й не стейджити». Перед кожною задачею й після неї контролер знімає **знімок робочої теки**
  як git-дерево, не чіпаючи index чи історію:
  `GIT_INDEX_FILE=$(mktemp)` (файл одразу видалити) → `git read-tree HEAD` → `git add -A` (з кореня репозиторію — тоді в знімок іде вся робоча тека) → `git write-tree` → хеш дерева.
  `.gitignore` діє, тож робоча тека скіла (`.superpowers/`) у знімок не потрапляє.
- Пакет для рецензента: `git diff --stat <знімок-до> <знімок-після>` і `git diff -U10 …` в один файл.
- Коли людина дозволила коміт — комітити **рівно перевірений знімок**, навіть якщо наступна задача вже в роботі:
  `git commit-tree <знімок> -p HEAD -m "…"` → `git update-ref refs/heads/<гілка> <новий> <старий HEAD>` → `git reset -q`
  (mixed: index = новий HEAD, робоча тека з поточними змінами лишається як є). Кілька задач — ланцюжком `-p`.
- Хеші знімків і рішення — у журналі скіла (`.superpowers/sdd/<план>/progress.md`); він переживає стиснення контексту.

## Чого не робити
- `git stash`, `git checkout -- …` чи `git reset --hard`, щоб «відокремити» задачу: зітре роботу виконавця, що триває
  ([git-checkout-discards-changes](git-checkout-discards-changes.md)).
- Рецензувати `git diff` робочої теки без знімка-бази: туди змішаються попередні незакомічені задачі.

## Як перевірити
`git log --oneline` показує по коміту на задачу; `git status --short` після `git reset -q` — лише зміни поточної задачі.
