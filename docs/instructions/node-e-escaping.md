# `node -e` у bash ламає бектики й `\n` у вставленому коді

## Коли застосовувати
Правиш файл однорядковим скриптом `node -e "…"` (заміна фрагментів) у Git Bash, і в новому тексті є
шаблонні рядки JS/TS (бектики, `${…}`) або `\n` усередині рядкових літералів.

## Що робити
- Код із бектиками, `${…}` чи `\n` у літералах вставляти інструментом редагування (Edit/Write), а не через `node -e`.
- `node -e` лишати для простих замін тексту без таких символів (документація, коментарі).
- Після будь-якої скриптової правки — `git diff` зміненого фрагмента або typecheck.

## Чого не робити
- Не покладатися на подвійне екранування (`\\\``, `\\\\n`) у `node -e` всередині bash: bash виконує
  бектики як підстановку команди, а `\n` перетворюється на справжній перенос рядка в коді.

## Як перевірити
`npm run typecheck` зелений; у диффі немає обірваних рядків чи порожніх аргументів на кшталт `api<T>()`.
