## 1. Концепція

Персональна (single-user) система моніторингу оголошень OLX.ua: напівавтоматичний збір за
збереженими пошуками, таблиця порівняння, статуси й нотатки, AI-допомога в оцінці описів,
історія цін і експорт у Notion.

**Чому власна система, а не готовий парсер:** жоден із відомих проєктів (`Parser-of-olx`,
`lerdem/olx-parser`, `darkov19/olx-telegram-bot`) не має UI з таблицею, статусами й нотатками; з
них узято лише підхід до збору (прихований API OLX).

**Принципи:**
- **Спершу вручну.** Скани, AI-аналіз, експорт — за кнопкою; автоматизація (cron) — опційна й пізня.
- **Ввічливість до OLX.** Мінімум запитів, паузи, без браузерної автоматизації.
- **Нічого не видаляти мовчки.** Фільтри й auto-disable лише позначають рядки, причина — у нотатці.
- **Людина має останнє слово.** Ручні рішення не перетираються автоматикою.
- **Нуль обов'язкових витрат.** AI працює і без платного ключа (ручний режим), хостинг — безкоштовні тарифи.

**Масштаб:** одиниці–десятки пошуків, до кількох тисяч оголошень на пошук (після глибоких сканів).
SQLite/libSQL достатньо; PostgreSQL не потрібен.

## 2. Користувацький сценарій

1. Створюю **пошук**: запит (+ синоніми), ціновий діапазон, за потреби — проєкт-групу.
2. **Сканую**: звичайний скан (швидко, верхівка видачі) або глибокий (уся видача, з аналізом
   обсягу перед запуском).
3. Переглядаю **таблицю**: сортування, фільтри, фото, опис, продавець, активність на OLX.
4. **Відсіюю шум**: локальні фільтри, AI-фільтр релевантності («чи лот справді продає товар»).
5. **Оцінюю**: AI знаходить мінуси/плюси в описах за моїми критеріями; AI Вибір ранжує найкращих.
6. **Веду кандидатів**: статуси (`interested` → `contacted` / `rejected`), нотатки.
7. Система сама позначає **зниклі** оголошення (`disabled`) і повертає ті, що ожили.
8. ⏳ Бачу **динаміку цін**, експортую добірку в Claude (MD) або Notion.

## 3. Функціональні вимоги

### 3.1 Пошуки
- ✅ CRUD пошуків, ручне сортування, архів, групування в проєкти (акордеони).
- ✅ Синоніми запиту (один пошук — кілька формулювань, злиття видач), генерація синонімів AI.
- ✅ Серверні фільтри OLX (ціновий діапазон) у запиті.

### 3.2 Збір даних
- ✅ Звичайний скан (≤3 запити) і глибокий скан (уся видача, авто-розбиття по ціні понад вікно
  пагінації OLX), двофазний режим «аналіз → звіт → запуск», зупинка скану.
- ⛔ Автоматичний fallback GraphQL → HTML — вимкнено з 2026-10-03 (OLX відповідає 403, `olx-api.md` §3); прогрес скану в UI; CLI-скан.
- ✅ Стійкість: частково зібране зберігається при збої чи зупинці.
- ⚠️ Verify-прохід: перевірка живості давно не бачених оголошень + дозаповнення опису/продавця — зараз не працює (OLX відповідає `403`, [P-005](./parking.md)).
- ⏳ Автоматичний скан за розкладом (`node-cron`, Етап 4, вимкнено за замовчуванням).

### 3.3 Таблиця оголошень
- ✅ Сортування, пагінація, видимість/порядок колонок, темна/світла тема, мобільна версія.
- ✅ Фото (галерея), опис (тултіп/модалка), продавець, категорія, «Активність» (`olx_status`).
- ✅ Статуси й нотатки з інлайн-редагуванням, bulk-дії.
- ✅ Локальні фільтри: ціна, міста, продавці, плюси, мінуси, категорії; інвертований режим.
- ⏳ Δ ціни + спарклайн історії цін (Етап 3).
- ⏳ Локальні фільтри за стоп-словами й діапазонами `params` (у типах закладено, не реалізовано).
- ⏳ Картка оголошення (drawer) з усіма `params` і графіком ціни.

### 3.4 AI-допомога (лише вручну)
- ✅ AI-фільтр релевантності, мінуси/плюси за критеріями, AI Вибір (ранжування кандидатів).
- ✅ Два рушії: авто (OpenRouter, ключ опційний) і ручний (промпт/ZIP для будь-якого чату чи агента).
- ✅ Експорт результатів аналізу (Excel/JSON).

### 3.5 Експорт та інтеграції
- ⏳ **MD-експорт для Claude** (Етап 3): вибрані оголошення компактною таблицею + описами для
  копіювання в чат («відкинь биті, порівняй, поранжуй»).
- ⏳ **Notion** (Етап 4): internal integration (`NOTION_TOKEN`, `NOTION_PARENT_PAGE_ID` у `.env`);
  перший експорт створює database (Title, Price, Status (select 1:1), City, URL, Note, Posted,
  Δ Price, `olx_id`); повторний — синк за `olx_id` (update існуючих, create нових). Лише
  app → Notion.

### 3.6 Експлуатація
- ✅ Локальний запуск без зовнішніх сервісів; деплой Render + Turso (безкоштовні тарифи).
- ✅ Доступ лише власнику (Google OAuth allowlist).
- ✅ Журнал помилок у UI.

| Етап | Скоуп | Критерій готовності | Стан |

## 5. Поза скоупом

- 🚫 Мультикористувацький режим (OAuth — лише «замок» на одного власника).
- 🚫 Двосторонній синк з Notion.
- 🚫 Автоматичний AI-аналіз (зі сканів/cron).
- 🚫 Браузерна автоматизація для збору (Playwright) — лише як крайній fallback за рішенням людини.
- 🚫 Дії на OLX від імені користувача (повідомлення продавцям, обране тощо).

## 6. Ризики

| Ризик | Мітигація |
| --- | --- |
| OLX змінить GraphQL-схему / HTML-розмітку | Інтерфейс `OlxFetcher` ізолює стратегію; авто-fallback GraphQL → HTML (вимкнено: 403, [P-005](./parking.md)); селектори в одному файлі; чекліст [`olx-api.md` §5](./olx-api.md) |
| Rate-limit / бан IP | Звичайний скан ≤3 запити з паузою 1–2 с; глибокий — батчі по 3 з паузою 3–6 с і жорсткими лімітами запитів; скани лише вручну |
| Вікно пагінації OLX (`offset ≤ 1000`) ховає частину видачі | Авто-розбиття глибокого скану на цінові діапазони; попередження при частковому покритті |
| Хибний auto-disable | Вісь `last_refresh_at`, лише після повного скану, поріг 2 промахи для звичайного скану, verify-проба, auto-reactivate, причина в нотатці |
| Галюцинації LLM | `evidence` перевіряється як підрядок опису; ручна перевірка перед записом; ручний override не перетирається |
| Витік PII / ключів | PII продавця не йде в промпти; секрети лише в `.env` |
| Квоти безкоштовного Turso | Батчинг записів, мінімум індексів на гарячих колонках, клієнтські агрегати; заміри скілом `turso-reads-playbook` |
| Різна структура `params` між категоріями | `params` зберігається сирим JSON; колонки таблиці — динамічні |
