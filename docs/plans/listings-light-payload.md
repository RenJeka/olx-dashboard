# План: легка відповідь `/listings` (опис і галерея — на вимогу)

> **Статус:** 🟢 активний (з 2026-10-04) · B2-легка зі S14 (рішення людини 2026-10-04); повна серверна пагінація — [P-008](../parking.md). Відкрите питання — пошук в описі (нижче).

## Контекст

S14 ([stability-baseline](stability-baseline.md)): на великому пошуку `GET /api/searches/:id/listings`
відповідає десятки секунд, пам'ять API під час відповіді — понад 80 % ліміту (ризик OOM). Замір на проді
(2026-10-04, пошук `iphone`): найважчі поля відповіді — `description` (близько половини тексту) і
`photo_urls` (близько чверті). Обидва в таблиці потрібні лише на вимогу (наведення, клік, AI-майстер).

Мета — прибрати їх із `/listings` і віддавати окремо; сортування й фільтри лишаються на клієнті, читання
Turso на відкриття пошуку не зростають.

## Файли

- `web/src/types/listings.ts`, `web/src/api/listings.ts` — тип рядка таблиці без важких полів; хуки деталей.
- `web/src/components/table/DescriptionTooltip.tsx`, `ListingsTableRow.tsx`, `PhotoCell.tsx`,

- `web/src/pages/ListingsTable.tsx` — пошук в описі (за рішенням нижче).
- Документація: `docs/architecture.md` (ендпойнти), `docs/structure.md`.

## Кроки

- [ ] Сервер: `/listings` без `description`, `photo_urls` (+ ознака `has_description`, щоб UI знав, чи є опис).
- [ ] Сервер: `GET /api/listings/:id/details` → `{ description, photo_urls }`; `POST /api/searches/:id/listings/details`
      з `ids` → те саме для набору (AI-майстер), з обмеженням розміру набору.
- [ ] Фронт: підказка й діалог опису, галерея — `useQuery(['listing-details', id])` при наведенні/відкритті;
      до завантаження — мініатюра / «Завантаження…». Оптимістичні апдейти кешу `['listings', …]` не ламаються.
- [ ] Фронт: AI-майстер (крок перегляду) — описи пакетом за `ids`.
- [ ] Пошук в описі — за рішенням людини (нижче).
- [ ] Тест сервера: `/listings` не містить важких полів; `details` повертає їх (Fastify `inject`).
- [ ] Замір після деплою (з людиною): час відкриття пошуку `iphone`, пік пам'яті API (Render MCP).
- [ ] Документація.

## Відкрите питання — пошук в описі

Зараз галочка «шукати в описі» фільтрує на клієнті за повними описами всіх рядків. Без описів у `/listings`
варіанти: (а) пошук в описі на сервері — запит повертає `id` збігів; (б) завантажувати всі описи лише коли
галочку ввімкнено; (в) прибрати пошук в описі.

## Test-cases

- Відкрити великий пошук: таблиця з'являється помітно швидше, пам'ять API — далеко від ліміту.
- Наведення на опис / мініатюру — підказка й галерея з'являються (після короткого завантаження).
- AI-майстер, крок перегляду — описи видно.
- Пошук в описі працює за обраним варіантом.
- Редагування статусу/нотатки в таблиці — без регресій.
