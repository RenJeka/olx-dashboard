# План: легка відповідь `/listings` (опис і галерея — на вимогу)

> **Статус:** 🟢 активний (з 2026-10-04) · B2-легка зі S14 (рішення людини 2026-10-04); повна серверна пагінація — [P-008](../parking.md). пошук в описі — варіант «а», на сервері (рішення людини 2026-10-04). Код готовий; лишився замір після деплою.

## Контекст

S14 ([stability-baseline](stability-baseline.md)): на великому пошуку `GET /api/searches/:id/listings`
відповідає десятки секунд, пам'ять API під час відповіді — понад 80 % ліміту (ризик OOM). Замір на проді
(2026-10-04, пошук `iphone`): найважчі поля відповіді — `description` (близько половини тексту) і
`photo_urls` (близько чверті). Локально після змін відповідь зменшилась приблизно вдвічі. Обидва в таблиці потрібні лише на вимогу (наведення, клік, AI-майстер).

Мета — прибрати їх із `/listings` і віддавати окремо; сортування й фільтри лишаються на клієнті, читання
Turso на відкриття пошуку не зростають.

## Кроки

- [x] Сервер: `/listings` без `description`, `photo_urls`; натомість `description_preview` (колонка «Опис» показує початок тексту — сервер читає лише перші символи опису) + `has_description`.
- [x] Сервер: `GET /api/listings/:id/details` → `{ description, photo_urls }`; `POST /api/searches/:id/listings/details`
      з `ids` → те саме для набору (AI-майстер), з обмеженням розміру набору.
- [x] Фронт: підказка й діалог опису, галерея — `useQuery(['listing-details', id])` при наведенні/відкритті;
      до завантаження — мініатюра / «Завантаження…». Оптимістичні апдейти кешу `['listings', …]` не ламаються.
- [x] Фронт: AI-майстер (крок перегляду) — описи пакетом за `ids` (порціями по 500).

- [x] Тест сервера: `/listings` не містить важких полів; `details` повертає їх (Fastify `inject`).
- [ ] Замір після деплою (з людиною): час відкриття пошуку `iphone`, пік пам'яті API (Render MCP).

## Рішення — пошук в описі

Варіант «а» (людина, 2026-10-04): пошук на сервері, запит повертає `id` збігів. Кожен пошук читає з Turso
рядки всього пошуку — лише коли ввімкнено «в описі» й після паузи в наборі.

## Test-cases

- Відкрити великий пошук: таблиця з'являється помітно швидше, пам'ять API — далеко від ліміту.
- Наведення на опис / мініатюру — підказка й галерея з'являються (після короткого завантаження).
- AI-майстер, крок перегляду — описи видно.
- Пошук в описі працює за обраним варіантом.
- Редагування статусу/нотатки в таблиці — без регресій.
