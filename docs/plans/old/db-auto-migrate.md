# План: автоміграція колонок схеми при старті (`initDb`)

> **Статус:** ✅ виконано (2026-09-29) · test-cases 1–5 прогнано на копіях БД (стара: +21 колонка, повтор 0; актуальна: 0; порожня: 0 ALTER; FK збережено; неможлива міграція → помилка без змін).

## Контекст

`initDb()` виконує лише `schema.sql` (`CREATE TABLE IF NOT EXISTS`): відсутні таблиці
створюються, а **нові колонки в наявні таблиці не додаються**. 2026-09-29 локальна БД від
2026-06-16 не мала 21 колонки → `SQLITE_ERROR: no such column: category_id` на
`GET /listings`; виправлено вручну скриптом. Та сама проблема чекає на прод-БД у Turso при
першій же новій колонці. До міграції на libSQL цю роль виконував `addColumnIfMissing`
(прибраний разом із better-sqlite3).

## Рішення

`initDb()` у три кроки, без парсингу SQL вручну:
1. Застосувати `schema.sql` до еталонної БД у пам'яті (`createClient({ url: ':memory:' })`).
2. Для кожної таблиці еталону, що **вже існує** в робочій БД, порівняти `PRAGMA table_info` і
   для відсутніх колонок виконати `ALTER TABLE … ADD COLUMN <визначення>`. Визначення колонки
   береться з `CREATE TABLE` еталону (`sqlite_master.sql`) — зберігаються `REFERENCES`/`CHECK`/
   `DEFAULT`; розбиття по комах верхнього рівня (з урахуванням дужок і рядків), коментарі `--`
   прибираються.
3. Виконати `schema.sql` на робочій БД (створює відсутні таблиці та індекси — індекси вже
   бачать нові колонки).

Обмеження SQLite (`ADD COLUMN` не вміє `PRIMARY KEY`/`UNIQUE`, `NOT NULL` без дефолту,
неконстантний `DEFAULT (datetime('now'))`) → зрозуміла помилка старту з назвою
`таблиця.колонка` і підказкою про ручну міграцію (rebuild), без часткових мовчазних змін.
Колонки, видалені зі схеми, **не видаляються** (лише додавання — безпечно).

`initDb()` повертає список застосованих `ALTER` (циклічний імпорт `logger.ts → db.ts` не дає
логувати в `db.ts`): `index.ts` логує через `app.log.info`, CLI (`scan.ts`,
`migratePostedAt.ts`) — `console.log`.

## Test-cases

1. **Стара БД** (копія бекапу `olx.bak-2026-06-16.db`, без 21 колонки) → старт/`initDb` додає
   рівно 21 колонку, повторний запуск — 0 змін (ідемпотентність), `GET /listings` → 200.
2. **Актуальна БД** → 0 змін, старт як раніше.
3. **Порожня БД** (нового файлу немає) → створюються всі таблиці та індекси, 0 `ALTER`.
4. **Колонка з `REFERENCES`** (`searches.project_id`) додається з FK у визначенні
   (`sqlite_master.sql` таблиці містить `REFERENCES projects(id)`).
5. **Неможлива міграція** (тимчасово додати в копію схеми колонку `NOT NULL` без дефолту) →
   старт падає з повідомленням, що називає `таблиця.колонка`; БД не змінена.
