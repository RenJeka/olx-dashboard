# План: копія прод-БД (Turso) у локальний файл

> **Статус:** ✅ виконано (2026-10-16) · не перевірено: перегляд таблиці оголошень в UI людиною

## Контекст

На новому ПК локальна БД `server/data/olx.db` порожня. Для розробки на реальних даних людина обрала варіант
«копія проду у файл» (альтернативи — порожня БД або гілка Turso — відкинуто: гілка витрачає квоту на кожне
читання в розробці). Turso CLI і `sqlite3` на Windows не встановлені, тож потрібен власний CLI на
`@libsql/client`.

Обмеження:
- прод — **лише SELECT**; Turso рахує прочитані рядки → keyset-пагінація за `rowid` (кожен рядок читається
  один раз, без `OFFSET`), без повторного `COUNT` на проді;
- токен проду до агента не потрапляє: людина задає його в змінних своєї сесії PowerShell;
- змінні джерела — **окремі імена** (`PROD_DB_URL`, `PROD_DB_TOKEN`), не `TURSO_*`: якщо людина забуде їх
  прибрати, `npm run dev` у тому ж вікні не піде в прод;
- наявний `olx.db` спершу перейменовується в бекап `olx-bak-<час>.db` (під `server/data/*.db` у `.gitignore`),
  далі запис **прямо в `olx.db`**: тимчасовий файл не перейменувати — libSQL на Windows тримає файл до виходу
  з процесу (перевірено 2026-10-16). Якщо відповідає `:3001` (працює `npm run dev`) чи є `olx.db-wal`/`-shm` — відмова
  до читання проду. Збій посеред копії → `olx.db` неповний, CLI друкує команду повернення бекапу.
