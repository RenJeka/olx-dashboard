# Запобіжник verify-проходу від 403 OLX

> **Статус:** ✅ виконано (2026-10-10) · рішення людини (варіант B + вимкнена кнопка) · коміт `3d3218d` у гілці `feat/criteria-categories` · test-case 3 перевірено агентом у браузері · обхід самого блоку — [P-005](../../parking.md)

## Контекст

- Verify-прохід («Перевірити неактивні») відкриває сторінку кожного оголошення напряму
  (`scraper/verifier.ts`). З 2026-10-03 OLX (CloudFront) відповідає `403` на будь-яку HTML-сторінку з Node
  ([olx-api](../../olx-api.md) §6); REST `api/v1/offers/<id>` — теж `403` (перевірено 2026-10-10).
- Наслідок: прохід робить до 50 марних запитів до OLX і пише в `scan_runs.error` довгий список
  `#id: http=403` — у діалозі «Сканування та статистика» це виглядає як нова помилка. Статуси не змінюються
  (`unknown`), дані цілі.

## Рішення

- **Сервер:** `403` кілька разів поспіль (`VERIFY_BLOCK_STREAK`) → прохід зупиняється, у `scan_runs.error` —
  одне коротке повідомлення з посиланням на P-005. Працює й для CLI (`npm run scan -- --verify`).
- **UI:** кнопка «Перевірити неактивні» вимкнена, в описі — причина. Перемикач `VERIFY_PROBE_AVAILABLE` у
  `web/src/constants.ts` (дзеркало `HTML_FALLBACK_ENABLED` сервера — той самий HTML-канал); при закритті P-005
  повернути `true`.
