## Decisions (і чому)

- **Суддя замірів — агент, ліміт 15 ¢** (людина): скрипт пише сирі виходи, агент розмічає файл міток. Витрачено ≈ $0.13.
- **Запобіжники в коді + легкий промпт генерації, без формату `kind`** (людина, рекомендація агента).
- **Дефолт — Haiku 5.5** (людина): у генерації ≈ 1 % протилежних пунктів проти 10–22 % у Gemini; Gemini раз зациклився
  ($0.027 за виклик, невалідний JSON).
- **Правила в промпті пошуку відкочено** (людина): на 60 оголошеннях ефекту немає (мінуси 55.6 → 55.8 %, плюси 82 → 80 %).
- **Автогрупування — за темою/аспектом, як мінуси людини** (людина: «без коробки», «без зарядного» → «не повна
  комплектація»). Реалізація (агент): модель лише називає аспект кожного критерію, групи складає код — пряме «згрупуй»
  порушувало навіть явні заборони.
- **Промпти — універсальні під будь-які категорії** (поправка людини): приклади з меблів, авто, одягу, техніки.

## Dead ends — не повторювати

- **Правила про числа/заперечення в промпті пошуку:** precision не змінився → відкочено. Причина низької точності
  мінусів — розмиті назви критеріїв («сервісна батарея», «не повна комплектація»), не промпт.
- **Промпт «згрупуй за аспектом» (без класифікації):** обидві моделі об'єднували «16 Гб + 512 Гб», «MacBook Pro + M1 Pro».
- **Python у bash-heredoc для правок TS з `\n`:** удруге справжній перенос у літералі → дописано в
  `docs/instructions/scripted-edit-assert.md`.
- **Кліки/скріншоти, коли панель браузера wmux у прихованому workspace:** → `docs/instructions/wmux-browser-hidden-pane.md`;
  перевірено через локальний API.
