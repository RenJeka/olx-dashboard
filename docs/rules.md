# Стабільні правила роботи

Правила, які не змінюються від сесії до сесії: документація, прод, хендофи, парковка, git, стиль. Міняти — лише за
прямим рішенням людини. Інваріанти продукту й стек — у [`AGENTS.md`](../AGENTS.md), процес задачі й
перевірки — у [`development.md`](development.md), поточний стан — у [`current.md`](current.md).

## Принципи документації

1. **DRY.** Кожен факт живе в одному місці (таблиця «Де живе факт» нижче; доменне — карта
   документації в `AGENTS.md`), решта лише посилається, не переказуючи. Перед записом — пошук (Grep),
   чи факт уже є.
2. **Без кількостей, що застаріють, у живих документах** (`current.md`, `instructions/`, `parking.md`,
   довідкові доки): скільки оголошень, тестів, файлів, рядків. Потрібне число — живим запитом.
   Хендофи й архівні плани — знімки з датою, там числа допустимі. Ідентифікатори (`P-003`, `S9`,
   `scan_runs.id`) кількостями не є.
3. **Дрібні файли.** Одна пастка — один файл в [`instructions/`](instructions/README.md); інші файли
   лише посилаються.
4. **Мова.** Документація й скіли — українською; імена файлів і тек — латиницею в kebab-case
   (мова коду й UI — `AGENTS.md` → «Конвенції»).
5. **Формати.** Хендоф, інструкція й запис парковки — за шаблонами з [`templates/`](templates/);
   план — за конвенцією з `AGENTS.md` → «Конвенції».

## Джерела істини

- **Код і `server/src/db/schema.sql`** — як система працює зараз. Документ розходиться з кодом —
  вірити коду, документ виправити (або спитати людину, якщо незрозуміло, що з них задум).
- **Прод (Render + Turso)** — що задеплоєно й що в прод-БД. Перевіряти MCP лише читанням (див.
  «Прод»); Turso — за `AGENTS.md` → «Turso-економія».
- **GitHub (`RenJeka/olx-dashboard`)** — стан CI, PR, гілок.
- **Цей репозиторій (`docs/`)** — правила, знімок стану, пастки, плани, історія сесій.

Якщо джерела розходяться — не обирати мовчки: показати розбіжність, перевірити живий стан, виправити
застаріле.

## Прод (Render, Turso, GitHub)

- Читання — вільно. Зміна стану (деплой, env, гілка сервісу, запис у БД, токени з правами запису,
  merge у `main` = автодеплой) — лише після явного «так» людини в поточному діалозі.
- Видалення (БД, гілок Turso, git-гілок, сервісів) — лише за прямою командою.

## Хендофи

- Ім'я `docs/handoffs/YYYY-MM-DD-<slug>.md`: дата — день закриття сесії за київським часом
  (системний годинник), slug — коротка тема латиницею. Кілька за день — різні slug.
- Хендоф — знімок стану, не розповідь. Історію не переписуємо заднім числом (виняток — вирізання
  секретів); шляхи в старих хендофах не «лагодимо».

## Парковка

- [`parking.md`](parking.md) — відкладені бажані зміни й бекло людини. Не для кроків активних планів
  (вони живуть у `docs/plans/`).
- Номер `P-NNN` стабільний і повторно не використовується. Наступний = найбільший номер у
  `parking.md`, хендофах і планах + 1; лічильника не зберігаємо.
- Запис береться в роботу → з'являється план у `docs/plans/`, у плані — посилання на `P-NNN`.
  Закритий запис прибирається з `parking.md` і згадується в хендофі сесії, де його закрили.

## Інструкції та скіли

- Нова пастка, глухий кут чи патерн — окремий файл в [`instructions/`](instructions/README.md)
  (скіл `instruction-add`).
- Процедуру з кроками активно пропонувати перетворити на скіл (`skill-from-instruction`): кроки
  лишаються в інструкції, скіл лише вказує на неї.
- Скіли — лише в `skills/`; `.claude/skills/` і `.agents/skills/` генерує `npm run skills:sync`
  (див. [`skills/README.md`](../skills/README.md)).

## Стиль відповіді

- Українською; усталені терміни — англійською. Коротко, результат спочатку.
- Людині — конкретні покрокові інструкції з клікабельними посиланнями й **абсолютними шляхами**
  ([absolute-paths-for-user](instructions/absolute-paths-for-user.md)); часто читає з телефону.
- Гіпотезу позначати рівнем упевненості; спростовану визнавати прямо. Рішення — за людиною.

## Git

- Коміт — лише за словом людини; повідомлення коміту й PR — англійською. Після змін — запропонувати
  текст коміту.
- У PR і комітах — без помітки про Claude Code (`Co-Authored-By`, `Claude-Session`, «Generated with»). Merge — «Create a merge commit». Гілки не видаляти без прямого
  запиту. PR і CI — [github-cli](instructions/github-cli.md). Коли зливати — `AGENTS.md` → «Перевірка».
